# SpaceX Spark Data Pipeline & Analytics Platform 🚀



**Полноценная ETL-платформа** для сбора, обработки, хранения и визуализации данных о запусках ракет SpaceX. Проект объединяет современные технологии обработки больших данных (Apache Spark), надежное хранение (PostgreSQL), интерактивную аналитику (Grafana) и полностью автоматизированный DevOps-цикл (Docker, GitHub Actions).

## 🏗 Архитектура и Диаграммы

### Общая архитектура системы

```
    🌐 SpaceX API
        │
        ↓ 📥 JSON Data
    ⚡ Spark ETL Application
        ├───────────┐
        │           ↓
        │    💾 Save to
        │       🗄️ PostgreSQL ────▶ 📊 Grafana Dashboards
        │
        ↓
    🛠️ CRUD Operations
        │
        ↔️
        │
    🖥️ User CLI Interface
```

### Диаграмма последовательности (Data Flow)
```
    ┌─────────────────┐
    │    🖥️ CLI       │
    │  (User Input)   │
    └────────┬────────┘
             │ 1️⃣ Загрузка данных
             ▼
    ┌─────────────────┐    HTTP GET    ┌─────────────────┐
    │    ⚡ Spark      │ ─────────────▶ │    🌐 SpaceX    │
    │   (ETL Engine)  │                │      API        │
    └────────┬────────┘ ◀───────────── └─────────────────┘
             │              JSON Response
             │ 2️⃣ JSON Parsing → DataFrame
             ▼
    ┌─────────────────┐    JDBC Write   ┌─────────────────┐
    │   📊 DataFrame  │ ──────────────▶ │   🗄️ PostgreSQL │
    │  (In-memory)    │                 │    (Tables)     │
    └─────────────────┘                 └────────┬────────┘
                                                  │ 3️⃣ Визуализация
                                                  ▼
                                         ┌─────────────────┐
                                         │   📈 Grafana    │
                                         │  (Dashboards)   │
                                         └─────────────────┘
```

## 🎯 Основные Возможности

- **Загрузка данных в реальном времени**: Получение актуальной информации о всех запусках SpaceX (миссии, ракеты, полезная нагрузка) через официальное открытое API.
- **Высокопроизводительная обработка**: Использование Apache Spark для распределенной обработки и трансформации JSON-данных.
- **Полный цикл CRUD операций**: Создание, чтение, обновление и удаление записей о запусках через интуитивный CLI.
- **Гибкие источники данных**: Работа как с live-данными из API, так и с локальным кэшем в Spark.
- **Мультиформатный экспорт**: Сохранение обработанных данных в CSV для анализа и в PostgreSQL для долговременного хранения.
- **Продвинутая визуализация**: Готовые дашборды в Grafana для анализа успешности запусков, активности по годам, статистики по ракетам.
- **Полная контейнеризация**: Готовый `Dockerfile` и `docker-compose.yml` для изолированного запуска всего стека (App + DB + Grafana).
- **Автоматизированный DevOps**: CI/CD пайплайны на GitHub Actions для автоматической сборки, тестирования и публикации образа в Docker Hub.

## 🚀 Быстрый Старт с Docker (Рекомендуемый способ)

**Разверните всю систему (приложение + БД + Grafana) одной командой:**
####  1. Клонируйте репозиторий
```bash
  git clone https://github.com/danisimover/SpaceXSpark.git
  cd SpaceXSpark
```

#### 2. Запустите все сервисы через Docker Compose
```bash
  docker-compose up -d
```
#### 3. Проверьте, что все контейнеры запущены
```bash
  docker-compose ps
```
#### 4. Откройте CLI приложения для первоначальной загрузки данных
```bash
  docker exec -it spacex-spark-app java -jar /app/SpaceXSpark-fat.jar
```
```
#### В меню выберите: 1 → "SpaceX API (с загрузкой в Spark)"
После запуска сервисы будут доступны:

Приложение CLI: Внутри контейнера spacex-spark-app

Grafana Dashboard: http://localhost:3000 (admin/admin)

PostgreSQL: localhost:5432, БД: spacex, Пользователь: postgres, Пароль: password
```

#### Остановка всех сервисов:

```bash
    docker-compose down
```
## ⚙️ Локальная Установка и Запуск

### Предварительные требования

- **Java JDK 21+**

- **PostgreSQL 16+** (опционально, для полного функционала)
- **Docker & Docker Compose** (опционально, для контейнерного запуска)

```bash

```bash

## Подробное описание операций CLI

### 📥 Загрузка данных из SpaceX API (Опция 1)

1. **Подключение**:  
   Приложение соединяется с [SpaceX API](https://api.spacexdata.com/v3/launches), чтобы получить данные о запусках.

2. **Парсинг JSON**:  
   Полученный JSON-ответ парсится в структурированный **Spark DataFrame**.

3. **Сохранение в память**:  
   Данные сохраняются в **in-memory кэш** Spark для последующих операций.

4. **Результат**:  
   ~111+ записей о миссиях SpaceX загружается в локальное хранилище.

---

### 📝 CRUD Операции (Опции 1-5)

1. **Добавить запуск**:  
   Ручное создание новой миссии (для тестирования).

2. **Просмотреть запуск**:  
   Детальная информация по номеру полета (`flight_number`).

   Пример вывода:
   ```json
   Номер запуска: 2  
   Дата: 2007-03-21T01:10:00.000Z  
   Место: Kwajalein Atoll  
   Успешен: Нет  
   Ракета: Falcon 1 (Merlin A)  
   Полезная нагрузка: DemoSAT [Satellite, United States]
### 📝 CRUD Операции (Опции 1-5)

- **Обновить запуск**:  
  Модификация полей существующей записи.

- **Удалить запуск**:  
  Удаление записи по идентификатору.

- **Посмотреть все запуски**:  
  Пагинированный список всех миссий.

---

### 💾 Экспорт данных (Опции 6-7)

- **В CSV**:  
  Сохранение **DataFrame** в файл `launches_export.csv` (локально).

- **В PostgreSQL**:  
  Запись всех данных в таблицы БД для долговременного хранения и визуализации в Grafana.

### 🔄 CI/CD Pipeline (DevOps)

Проект использует два автоматических пайплайна в GitHub Actions:

#### 1. **CI Pipeline (Continuous Integration)**

- **Триггер**: Push или Pull Request в ветку `master`.
- **Этапы**:
    1. Checkout кода.
    2. Установка JDK 21.
    3. Кэширование Maven зависимостей.
    4. Сборка fat JAR: `mvn clean package`.
    5. Сборка Docker образа.
    6. Валидация: Запуск контейнера и проверка логов.
    7. Очистка (остановка контейнера).

**Назначение**: Гарантия, что каждый коммит собирается и базово функционирует.

---

#### 2. **CD Pipeline (Continuous Deployment)**

- **Триггер**: Push в ветку `master` (после успешного CI).
- **Этапы**:
    1. Checkout кода.
    2. Логин в Docker Hub через Secrets.
    3. Сборка и тегирование образа.
    4. Пуш образа в Docker Hub: `danisimovers/spacex-spark:latest`.

**Назначение**: Автоматическая публикация обновленного образа в публичный реестр.
